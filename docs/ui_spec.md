# 3ペインUI仕様

対象読者: フロントエンド（`frontend/`、React + Vite + TypeScript）に触れる開発者。画面レイアウトと UX 導線を扱う。コンポーネント構成は `docs/architecture.md` 8節。

## 「開く」ダイアログ（#165）

左メニューの「🔗 開く」（「🔍 検索」の直後）は、URL・AT URI・`@` で始まるユーザーID・`did:plc:` を入力するモーダルを開く。「開く」で必要なら取り込んでプロフィールかポスト詳細へ遷移し、判別できない入力はモーダル内にエラーを出す。

案内文は通常「URLまたはユーザーID」、画像認識中は「QRコードまたは文字をかざしてください」。入力欄右端のカメラボタンで画像認識を始め、背面カメラを優先し、各フレームを QR デコーダーへ、2秒ごとに OCR へ渡す。条件に合う文字列を認識したら入力欄に戻す。モーダルを閉じたら MediaStream と OCR Worker を止める。

## 通報

投稿カードと他ユーザーのプロフィールの「⋯」メニューに「⚠️ 通報」を出す。通報モーダルは Bluesky 準拠の理由を必須とし、自由記述は300文字/1000バイト以内。管理画面の「通報」タブは未処理を先頭に、対象リンク・クローズ・凍結/投稿削除・内部コメント・リモート転送を出す。対象アクターが既に凍結済み（`AdminReport.subject_suspended`）なら「ユーザー凍結」ボタンの代わりに「凍結済み」バッジを出す。管理者が通報の対象リンクから開く投稿詳細・プロフィールでは、followers-only/direct の投稿も見える。

## 1. 3ペイン共通レイアウト・グリッド構造

* **左ペイン**（`flex-basis: 240px`）: メインメニュー。
* **中央ペイン**（`flex-basis: 600px`）: メインのコンテンツ。
* **右ペイン**（`flex-basis: 500px`）: 画面に応じて中身が変わるコンテキスト領域。

幅が狭くなると次の順で縮退する。
1. **769〜1380px:** 左ペインがアイコンのみ（72px）に畳まれる（3ペインの必要幅が1340px → 1172px になる）。
2. **769〜1220px:** 右ペインが下に折り返され、縮小左ペイン＋中央ペインの2ペインになる。
3. **768px以下:** モバイル（1.1節）。

ブレークポイントには余裕を持たせてある。`width` メディア特性は縦スクロールバーを含む幅で評価されるが、実際に使える幅はスクロールバー分（15〜20px）狭いため。

- `HomePage`/`ProfilePage`/`ListsSettingsPage` は `useIsNarrowViewport` で「右ペインが折り返される幅か」を JS でも判定し、狭ければ右ペインの中身を中央へ差し込む。この値は CSS で `.right` が折り返される `max-width`（上の2.）と必ず一致させる。ずれると空の `.right` だけが残る。
- 左ペインが畳まれている間は、アイコンのホバー/フォーカスで右にキャプションを出す（`LeftNav.tsx` の `.navTooltip`）。下に出すとマウスが吹き出しに乗って消えず、下のアイコンを押せなくなるため。`.leftNav` は `position: sticky` と `z-index: 10` を持つ（`auto` だと DOM 順で後ろの中央ペインの要素が手前に出る）。
- 右ペインは `.right` 内の `.rightScroll` が `overflow-y: auto` で独自に縦スクロールする。CSS では「縦だけスクロールして横ははみ出し可」にできない（片方だけ visible にできない）ので、右ペインの外へはみ出すポップアップは `position: fixed` と実測座標で置く（`NoteHoverPreview` の `side`）。`.right` は `z-index: 100`（NoteCard 内の z-index 要素に隠れないように）、`NoteHoverPreview` の `.popup` は 101（fixed 要素はルートのスタッキング文脈で `.right` と比べられるので、上回らないと右ペインの下に潜る）。Modal も 100 だが DOM 順で後ろなので最前面になる。

### 1.1 モバイルレイアウト（幅768px以下）
* 左ペインを隠し、画面下部に5つのフローティングボタンを並べる（1つの `position: fixed` コンテナを flex の `space-between` で均等配置）: メニュー（ドロワー、DM 未読バッジ付き）・ホーム・通知・検索・投稿。
* 中央ペインと右ペインは縦積みの1カラム。
* `body` だけに `overflow-x: hidden` を付ける（`index.css`）。子孫が横にはみ出してもレイアウトビューポートが広がらず、フローティングボタンの位置がずれない。`html` には付けない（CSS の body → viewport の伝播が効かなくなる）。`html, body` の両方や `.shell` 等の div に付けると、`overflow-x`/`overflow-y` の連動でそれが独自の縦スクロールコンテナになり、`window.scrollY` ベースのスクロール位置復元が壊れる。

### 1.2 NoteCardヘッダー（投稿者名・日付・アカウント行）

* 1行目: 表示名（あふれる分は ellipsis）と右寄せの投稿日付。日付は常に全文を出し、表示名側を縮める。
* 2行目: アカウントID（`@user@domain`、配送先/公開範囲の小バッジ込み、ellipsis）と、その右の「リモートサーバー表示」。
  * ローカルと `remote_seiran` には出さない。`remote_seiran` はアカウントID直後の小バッジだけで、アイコンは Twemoji の 🌃 左半分と 🏙️ 右半分を合成した自前 SVG（`assets/seiran-skyline.svg`。seiran 同士を外部プロトコルの記号ではなく「同じ都市の景色」で表す）。
  * Fedi はサーバーアイコン（`note.user.instance.iconUrl`、無ければ 🌐）＋サーバー名（`instance.name`、nodeinfo 未取得ならドメイン名）。Bsky は Bluesky ロゴ SVG ＋「Bluesky」固定。
  * ローカル投稿の配送先バッジも Bsky 分は Bluesky ロゴ SVG。
  * 背景色はバックエンドが解決した `instance.themeColor` をそのまま使う（フロントに software 別の色分けは無い）。暗い色もありうるので、文字は常に濃色で白いドロップシャドウで縁取る。
  * アカウントIDの右からカード右端まで広がり（`flex: 1 1 0`）、あふれる分は ellipsis。
* リポストラッパーでは、rail（🔁＋リポストした人＋日時、`RepostRail`）と元投稿カードの日付はそれぞれの詳細（ラッパー自身の `/notes/:id`、元投稿の `/notes/:renoteId`）へのリンク。親から `linkToDetail={false}`（ポスト詳細の主役カードで自己参照リンクを消すフラグ）が来ても元投稿カードには伝播させない。元投稿が非公開・未取り込みで埋め込めない場合も rail の日時リンクは出す。

## 2. 各画面における右ペインの動的コンテキスト・スイッチ

中央ペインの画面に応じて右ペインの内容を切り替える。

### 2.1 【タイムライン画面】表示時

* ホーム/ソーシャルは自分とフォロー中の「ひかえめ」「プライベート」投稿を出し、ローカル/グローバルは投稿者本人が見ていてもそれらを出さない。フロントでもローカル/グローバルの取得結果を同じ条件で最終フィルタする。
* **右ペイン:** タブ式で、既定は【クイック通知】（トレンドは未実装のため）。
  * **【クイック通知】**: 自分への反応のストリーム（新着順の無限スクロール、`docs/protocols.md` 8節）。
    * 通知者の名前は常にプロフィールへのリンク。対象ポストがある通知（リプライ・リアクション・メンション・リポスト・引用）は通知文全体（アイコン以外）がそのポストへのリンクで、ホバーで対象ポストの投稿者と本文をポップアップする（`NoteHoverPreview`、初回ホバー時に取得、120ms 遅延で閉じる）。CW 付きならポップアップも CW 案内と開閉ボタンだけを先に出す。
    * リポスト通知だけは、ポップアップはリポスト元（本文のある投稿）を、クリック遷移はリポストラッパー自身を指す（`NotificationsPanel.tsx` の `resolveTargetNoteId`/`resolveClickTargetNoteId`）。
  * **【トレンド＆検索】**: 検索窓とトレンド（トレンド集計は未実装）。

#### 投稿フォームのリッチ入力（#94）

* 本文は送信時にプレーンテキストへ直列化するが、入力面は `ComposerEditor`（contenteditable）で装飾表示する。iOS Safari の自動ズームを避けるため 16px を保つ（`docs/coding_rules.md` 12節）。
* `@` または絵文字の開き `:` からカーソルまでのトークンで、投稿欄専用のアクター前方一致 API または公開カスタム絵文字一覧から候補を入力欄の下に出す。アクターはハンドルの前方一致だけ（表示名・途中一致は対象外）。完成済みの閉じ `:` では出さない。上下キー・Tab・Shift+Tab で選び、候補選択中の Enter だけを置換に使う（未選択の Enter は改行1個）。
* IME 変換中は候補のキー操作を横取りせず、未確定の DOM を装飾・再構築しない（確定後にプレーンテキストへ同期）。未確定文字は contenteditable 自身の DOM に入るので、入力開始時点でプレースホルダーを隠す。非同期の ID 既知判定で装飾 DOM を更新するときは caret を保存・復元する。
* ローカルユーザーの候補は入力に合わせる: `username` の前方一致なら `@username`、`username@` なら `@username@local.domain`、ローカルの Bsky ハンドル一致なら `@lower(username).local.domain`（Bsky ハンドルは小文字のみ）。完成したメンションは、actors で完全一致すれば水色背景・青太字、未解決ならピンク背景・赤太字。
* 完成したローカルのカスタム絵文字は、NoteCard と同じく閉じコロンの直後が文末か英数字・`_` 以外のときだけ、行高（1.6em）いっぱいの不可分な画像にする。左右キーは絵文字の内部に入らず、直前/直後の Backspace は隣のコロンだけを消して通常テキストに戻す。
* Bluesky 配送オンの間はカスタム絵文字を画像にせず警告色のテキストのままにする（Bsky は本文にカスタム絵文字を埋め込めない）。登録済みの shortcode があれば Bluesky 配送ボタンに ⚠️ バッジと赤みがかった黄色の枠を付け、ツールチップに警告文を足す。

### 2.2 【ユーザー詳細画面】表示時（左右並列プロフィールレイアウト）
自己紹介やメタデータが長いプロフィールでもスクロールが苦にならないようにするレイアウト。

* **ログイン不要**（`/:acct`、`/@handle`、旧 `/profile?q=`）。未ログインでは対ユーザー操作メニューの代わりに「フォローするにはログインするか、ユーザーIDをいつものサーバーで開いてください」と表示する。
* **中央ペイン:** ヘッダー、アイコン、Bio、フォロー数・フォロワー数（クリックで右ペインの対応タブへ）、ピン留めポスト。DID/URI の生の識別子は出さない。
  * Bio とキーバリュー項目（key/value とも）の `:shortcode:` はカスタム絵文字画像にする（ローカルは `custom_emojis`、リモート Fedi は `emoji_map`、Bsky は展開しない）。
  * Bio は本文と同じ `RichHtml`（`dangerouslySetInnerHTML` 不使用）で出す。リモート Fedi/`remote_seiran` の bio は HTML なので本文と同じ許可リストでサニタイズして保存したものを、ローカル/Bsky の bio はプレーンテキストなので表示直前にエスケープ＋裸URL/メンション記法のリンク化＋改行の `<br>` 化をして（`lib/profileHtml.ts`）通す。
  * キーバリュー項目は key:value = 4:6 の固定比率、key は右寄せ、value も `RichHtml`。
* **bio/キーバリュー内のリンクのサイト内化:** 裸URLと、プレーンテキストの bio のメンション記法（`@user@host`・`@handle.bsky.social`）について、リンク先が Fedi/Bluesky の実在ユーザー・投稿だと分かったら seiran 内のページへのリンクに差し替える。
  * ユーザーへのリンクは本文のメンションと同じ `UserLinkTag`（先頭に顔アイコン、ホバーでフォロースイッチ、右クリックで対ユーザー操作メニュー）。投稿へのリンクは内部遷移だけ。
  * 判定は WebFinger ではなく（`acct:` 形式にしか使えない）、AP の Content-Negotiation での直接取得か Bsky AppView で非同期に行い、`link_resolutions` に陽性・陰性ともキャッシュする（陰性は48時間で再調査）。未キャッシュの URL があれば `Job::LinkResolve` を積み、完了は WebSocket の `linkResolved`（ログイン中のクライアントに `broadcast_all`）で通知して表示を切り替える。
  * `RichHtml` は既存の `<a>` だけでなく地の文の裸URL・メンション記法もリンク化する（Misskey 等は profile_fields のメンションを `<a>` にせず送ってくる）。`<a>` の内側では二重リンクを避けて検出しない。`<a>` のテキストが `@user@host` 形状で `href` と食い違う場合は、テキストの解決結果を優先する（リモートがメンションを誤った URL で送ってくることがある）。
* **背景画像（バナー）:** `banner_url` があればアイコンの上に 16:5 で出し、顔アイコンを背景画像の内側左下寄りに重ねる。無ければアイコンのみ。
* **アカウントID:** ローカルと `remote_seiran` は Fedi 形式（`@username@domain`）と Bsky 形式（`@username.domain`、`remote_seiran` は `at_handle`。未解決なら Bsky 行を省略）の両方を2行で出す。リモート（fedi/`remote_seiran`/bsky）は NoteCard と共通のサーバー名表示（`lib/format.ts` の `remoteServerBadgeInfo`）も出す。凍結中のアクターは Fedi 形式の行の後に【凍結中】を出す（`is_suspended`）。
* **右ペイン:** タブ式（【アクティビティ】【フォロー中】【フォロワー】）。
  * 【アクティビティ】（既定）: 投稿とリアクションのイベントを時系列で混ぜて出す（`ProfileFeedList`、`GET /api/users/posts?includeReactions=true`）。投稿は通常の `NoteCard`。リアクションは通知と同じ体裁の `ReactionEventCard` で「[リアクション画像] [対象ポストの投稿者]のポストにリアクションしました」の1行（「誰が」は本人なので書かない）、クリックで対象ポストへ。カーソルは投稿・リアクション共通の `until_id`（同じ Snowflake 名前空間）。
  * 【フォロー中】【フォロワー】: アクター一覧の無限スクロール。`actor_id` を持たないリモートアクター（未登録の Bsky ユーザー等）はタブを出さず投稿一覧だけ。
* **スクロール:** 中央と右のスクロールを独立させ、右をどれだけ遡っても中央のプロフィールは固定される。
* **狭幅**（右ペインが下に落ちる幅）: ピン留めを独立セクションにせず、タブシートの先頭タブ【ピン留め】にする（無ければ【アクティビティ】が先頭）。タブシートは中央ペイン最上部に sticky。広幅ではピン留めは中央ペインに固定表示し、右ペインのタブシートは sticky にしない。
* **対ユーザー操作メニュー（`ActionsMenu`）:** 自分以外のプロフィールで、フォロー・ミュート・リポストミュート・ブロック・通報（それぞれ解除も）を1つのケバブメニューにまとめる。フォローは独立ボタンとしても併設する。ブロック（フォロー関係の強制解除を伴う、`docs/protocols.md` 10節）は確認モーダルを挟む。相手からブロックされていれば「このユーザーからブロックされています」と出してフォローを無効化する。相手が自分をフォローしていれば、フォローボタンの左に「フォローされています」を添える（`is_followed`）。
  * 「リスト"〇〇"に追加/から外す」も並ぶ。メニューを開いた時点で `GET /lists/membership/:actorId` で全リストと所属状態を1回で取り、はみ出さないよう作成順の先頭5件だけ出す（6件目以降はリスト設定画面で）。長いリスト名は ellipsis、`title` で全文。`actorId` の無い対象では出さない。
* **リポストミュート:** ミュート・ブロックと独立したフラグ。対象の通常投稿は出したまま、その人のリポストだけをホーム/ローカル/グローバルから消す（本人のプロフィールでは出る）。
* **対ユーザー操作の入口**: プロフィールのケバブメニューに加え、NoteCard のユーザー名・アイコンの右クリック（`UserContextMenu`）、通知アイテムとリアクションイベントのアバター・名前の右クリック（`UserLinkTag`）でも同じメニューを出す（対象は右クリックした名前の持ち主。リポストの「🔁 誰々さんがリポスト」ならリポストした人、引っ越し通知の移転先リンクも対象）。ホバーのフォロー状態スイッチ（`UserHoverPopover`）も同じ場所で使える。対象の変換と自分判定は `lib/userRelationship.ts`（`toRelationshipTarget`/`isSelfUser`）。
  * フォロー・ミュート・ブロック・リポストミュートの状態はタイムライン API の応答に事前付与されている（`attach_relationship_flags`）ので、NoteCard は問い合わせずに表示できる。状態は `stores/userRelationshipStore`（キー `profileQuery(username, domain)`）に一本化し、どこで操作しても画面内の同じユーザーの表示すべてに反映する。
* **フォロー承認待ち:** プロフィールの承認待ち表示にフォロー解除ボタンを併設し、承認前のリクエストを取り消せる。NoteCard のフォロースイッチも承認待ちで操作すると同じ解除 API を呼ぶ。

### 2.2b 投稿カード（`NoteCard`）のアクションメニュー
* 返信・引用・リポスト・リアクション・ケバブメニューの5つをアイコンのみのボタン列にする（文言は `title` だけ）。同じ操作をケバブメニューにも持たせる。
* 各アイコンの横に件数（返信・引用・リポスト・リアクション合計）。0は出さず、1000以上は `K`（小数1桁）、100万以上は `M` で3桁以内に収める（`formatCount`）。
* リポスト済み・リアクション済みはボタンの枠（`actionBtnActive`）で表す。リポストできない非公開投稿では薄く表示する。
* ピン留めは自分の投稿だけ、メニュー内だけ。
* 削除も自分の投稿だけ、メニュー内に赤字で出し、確認モーダルを挟む（連合先・Bluesky への取り消し配送を伴う不可逆操作）。

#### 添付画像のライトボックス（`ImageLightbox`）
* 静止画をクリックするとページ内のライトボックスを重ねる（タイトルバー・枠の無い画像ビューア）。背景・画像自体のクリック、Esc、ブラウザバックで閉じる。開くときに `history.pushState` で1エントリ積み、`popstate` で閉じる。UI 操作で閉じるときも `history.back()` でそのエントリを消費し、履歴に残さない。
* 複数の静止画は左右矢印キー・左右スワイプ・前後ボタンで移動する。先頭では前ボタン、末尾では次ボタンを出さない。
* ホイール/ピンチで100〜500%にズームでき、背面へのホイール伝播は `preventDefault` で止める。ズームは画像を囲む枠（`imageWrap`）ごと `transform: scale()` するので、枠が画面いっぱい・画面外まで大きくなる（固定の窓越しに拡大する虫眼鏡的な見え方ではない）。
* ズーム中はドラッグ/指1本でパンできる。実際に動いたときだけクリックの「閉じる」を抑止する。パン位置は「等倍の矩形が拡大後の矩形に常に内包される」条件で clamp する（許容範囲 `(scale-1)×素のサイズ/2`）ので、ズームアウトすると自然に中央へ戻る。画像の切り替えや開き直しで100%・中央に戻す。
* 閲覧注意の画像がぼかし中はズームを無効にする（解除ボタンごと拡大されるため）。
* 幅600px以下では余白なしで画面いっぱいに出す。ページめくりボタンは `position: fixed` なので画像に重なってよい。
* 最大表示は CSS で1024×1024px（`object-fit: contain`）。アップロード時の最大リサイズ2048px（`storage/image.rs`）は Retina の2倍密度でこの大きさを見込んだもの。
* 閲覧注意の画像はカード上で初期状態をぼかし、右上の 👁️ でだけ解除する。解除後に画像をクリックするとまたぼかす。ぼかした画像から開いたライトボックスもぼかしたままで、👁️ でだけ解除できる。閉じると解除状態は捨てる。

#### CW・長い投稿
* CW 付きの投稿は警告文だけを出し、ボタンで本文・添付・URLカード（埋め込みプレーヤーを含む）・アンケート・引用をまとめて開閉する。閉じている間はそれらのコンポーネント自体を描画しない。リポストの元投稿は別カードとして CW 状態を独立に持つ。CW 警告文の `:shortcode:` も `Note.emojis` で画像にする（通常カードと引用カードの両方）。
* **縦に長い投稿の折りたたみ:** 本文・添付・URLカード・アンケート・引用をまとめたブロック（CW 展開後の中身、アクション行は含まない）の実測の高さが幅の62.5%を超えたら、ブロックをクリップして下端にグラデーションのフェードを重ねる。
  * 「全部表示」ボタン（アクセントカラー塗り・白文字、左は本文と同じ50pxインデント、右はブロック右端に揃える）はブロックの下に積むと折りたたんだのに元より長くなりうるので、最下部に `position: absolute` で重ねる。
  * 高さは描画前に静的に決まらないので、`ResizeObserver` でクリップされない内側要素の `contentRect` を監視する。
  * 押すと展開してボタンは消え、畳み直しはできない。
  * フェードの終端色はカードの背景色（`--card-bg`、ライトテーマでは `transparent`）ではなく、実際に描画される不透明な色 `--card-bg-opaque`（ライトは `--bg`、ダークは `--card-bg`、`index.css`）を使う（透明同士だと効果が消える）。
* WebSocket で出てきた新着も通常 API の完全なデータで補完するので、アンケート・添付・引用がリロード無しで出る。
* リモートの添付・アバター・カスタム絵文字はメディアプロキシ経由で、同一オリジンの画像は直接出す（`docs/architecture.md` 7節）。

#### GIFアニメの自動再生表示
* `NoteAttachment.isGif` が真の動画（GIF ピッカー由来、または `presentation:"gif"`）は `HlsVideo` を自動再生・ミュート・ループ・コントロール無し（`autoplay muted loop playsinline`）にする。通常の動画は `controls` 付きで、再生するまでポスター画像のまま。
* HLS（`.m3u8`、Bsky 動画全般）はメディアプロキシを通さず動画CDN（`video.bsky.app`、CORS 許可済み）を直接参照する。プロキシは `application/vnd.apple.mpegurl` を許可せず、プロキシ経由だとプレイリスト内のセグメントの相対パスも解決できないため（`NoteAttachments.tsx`）。ポスターは通常の画像なのでプロキシ経由。
* HLS は `src` を JS で後からセットする（hls.js の `attachMedia`、Safari ネイティブは `video.src` 代入）ので、`autoPlay` 属性だけでは再生が始まらない。GIF 表示では、hls.js は `MANIFEST_PARSED`、ネイティブは `src` 代入の直後に `video.play()` を呼ぶ（`HlsVideo.tsx`）。
* HLS 以外のリモート動画は、`<source>` をプロキシ経由・直URLの順に2本並べる。プロキシが容量上限（25MiB）等で失敗したらブラウザが直URLへフォールバックする。自インスタンスの動画は1本だけ。

#### URLカード（`LinkCard`）
* 添付の直下に `Note.linkCards` を並べる（Bsky は0〜1件、Fedi・ローカルは複数ありうる。`key={card.url}`、`indent` で通常カード/引用カード内のインデントを分ける）。フロントは個別サービスの URL を解析せず、`card.embedSrc` の有無だけで3種に振り分ける。
  * **埋め込みプレーヤー**（`embedSrc` あり）: 最初はサムネイルと再生ボタンだけで、クリックしてから `embedSrc`（バックエンドが oEmbed で解決し許可リストで判定済み）の iframe を読み込む。iframe には `sandbox`（トップレベル遷移禁止等）を付ける。対象サービスは管理画面の許可リスト（既定 YouTube/Spotify/Apple Music/SoundCloud/Vimeo）で決まる。
  * **x.com / twitter.com**（`embedSrc` なし）: サムネイル・タイトル・説明のカードで、クリックしてから `platform.twitter.com/widgets.js`（複数カードでも1回だけ）でツイートを埋め込む。
  * **その他**: サムネイル・タイトル・説明・ドメインのカードで、クリックで新しいタブに開く。
  * どれもクリックするまで埋め込みを読み込まない（第三者トラッキングを既定で避ける）。

#### 絵文字リアクションピッカー（`ReactionPicker`）
* トリガーで `Modal`（`EmojiPickerPanel`）を開く。検索欄＋タブ（よく使う/絵文字/カスタム）＋グリッド。
* 検索欄に入力するとタブを隠し、カスタム絵文字（shortcode/タグの部分一致）と Unicode 絵文字（英語名と CLDR アノテーションの部分一致）を横断して出す。
* 「よく使う」は自分が今付けているリアクションの頻度集計（`GET /api/reactions/frequent`）。1投稿1リアクションなので過去の履歴ではなく現在の集計の近似。
* 「絵文字」「カスタム」はカテゴリ別のセクション（Unicode は `unicode-emoji-json` のグループ、カスタムは `custom_emojis.category` のアルファベット順で、未設定は末尾の「未分類」）。検索結果と「よく使う」はフラット。
* 「カスタム」は数千件になりうるので、セクションをまたいで200件（`GRID_PAGE_SIZE`）ずつ描き、末尾のセンチネルが見えるたびに足す。Unicode（約1,900件）は一括で描く。
* Unicode 絵文字データは独立チャンクで、ピッカーを開くまで読み込まない。
* カスタム絵文字は実寸の縦横比（`GET /api/emojis` が返す）に応じてセルを1〜4カラム（`emojiAspectSpan`、閾値2.2/3.4/4.6、1カラム36px）に広げて横長のまま出す。画像幅は `emojiSpanWidthEm`（`1.8 * span - 0.3`em）。Unicode とフォールバック表示は常に1カラム。
* `EmojiImage` は `media_files.blurhash` を canvas にデコードしたプレースホルダを先に出し、本画像の `onLoad` でプレースホルダを DOM から除く（重ねないので透過部分にプレースホルダ色が透けない）。

#### リアクションチップのホバーポップオーバー（`ReactionChips`）
* チップ（NoteCard 下部・ポスト詳細）のホバーで、付けた人の一覧（`GET /api/notes/:id/reactions/:content/actors`、新しい順・最大50件）をポップオーバーする。初回ホバーで取得し、120ms 遅延で閉じる（`ReplyIndicator` と同じ）。
* 公開投稿なら未認証でも見られる（可視性チェックは `get_note` と同じ）。

### 2.3 【ポスト詳細（会話ツリー）画面】表示時
* **ログイン不要**（`/notes/:id`）。可視性は各 API が判定する。未ログインで書き込み操作をすると 401 のエラートースト（明示的なログイン誘導は投票だけ）。
* **未ログイン時の左メニュー**: 最下部のユーザーチップが `/login?redirect=<現在のパスとクエリ>` への青い全幅ボタンに替わり、ログイン後に元の画面へ戻る。ログアウトボタンは出さない。左メニューが畳まれる幅ではラベルの代わりに 🔑。
* **中央ペイン:**
  * ターゲットポストが返信なら、返信先を小さい体裁・幅80%（`NoteCard` の `small`、左をターゲットと揃え右を空ける）で直上に出す。最初は直近の親1件だけを読み、その小カードの「↩️ 返信」（`ReplyIndicator`）で遷移せずにもう1段上を積み上げていける（スレッドの根まで何段でも）。積み上げたチェーンはポストIDごとに記憶する（2.4節）。
  * 初回訪問時（記憶したスクロール位置が無いとき）、読み込んだ返信先が長くて本体が画面外に押し出された場合だけ、`scrollIntoView({ block: "nearest" })` で本体が見える位置まで動かす。
  * 3ペイン表示のときは「返信」（下のモード2）を右ペインのタブから外し、ターゲットの下の常設セクションとして中央に出す（プロフィールのピン留めと同じ考え方）。狭幅では右ペインのタブのまま。
* **右ペイン**（タブシートは右ペイン上端に sticky）:
  * **【投稿者】**（`AuthorPanel`）: 投稿主のプロフィール概要（アイコン・名前・アカウント・自己紹介・フォロー数）と固定ポスト。概要はプロフィールへのリンク。リポストラッパーではリポストした人。
  * **【返信】**（`ReplyThreadPanel`）: 直系の返信・引用を再帰的に辿るツリー。`GET /api/notes/:id/replies`（`WITH RECURSIVE` で深さ20・最大200件）のフラット配列を `replyId`/`quoteId` でツリーにする（Misskey の `notes/children` の考え方に倣った内部 API）。
  * **【前後のポスト】**: タブを開くとすぐ読み込み、ターゲット（拡大表示）の前後の投稿を最大5件ずつ出し、ターゲットの位置へ自動スクロールする（連投や直前のリポストの文脈を一気読みできる）。上から「もっと新しい投稿を読み込む」→ 新しい投稿 → ターゲット → 古い投稿 →「もっと古い投稿を読み込む」。ボタンは `GET /api/notes/:id/context` に `before_id`/`after_id` を渡して続きを取る（`before_limit`/`after_limit` を0にすると片方向だけ）。中央ペインには複製しない。
  * **【リアクション】**（`ReactionListPanel`）: 絵文字ごとにグループ化し、付けた人の一覧を常に展開して出す（絵文字ごとに並列取得）。
  * **【リポスト】**（`RepostListPanel`、`GET /api/notes/:id/reposts`）: リポストした人と時刻。同じ人の複数回もその数だけ並ぶ。取り消し済みも履歴として出すがリンクにしない。取り消されていない行はそのラッパーの詳細へ。
  * **【元投稿者】**（リポストラッパーのときだけ）: 元投稿の書き手を `AuthorPanel` で出す。タブは末尾に足す（`noteDetailTab` はポストをまたいで保持するインデックスなので、途中に挿入すると通常ポストとタブの意味がずれる）。

### 2.4 右ペインにおけるサブタブ・ステートの維持ルール
* ポスト詳細を別のポストに切り替えても、右ペインのアクティブなサブタブ（例:「前後のポスト」）はセッション内で保つ。タイムラインのポストを順にクリックするだけで、右ペインで投稿者の前後の文脈を覗き続けられる。
* ポスト詳細のタブは URL の `?tab=` にも `replace` で同期する（戻るの段数は増えない）。リロード時は `?tab=` を優先する。
* ホーム右ペインのタブシート（【通知】/【トレンド・検索】）は `top={0}` で右ペイン上端に sticky（直上に他の sticky 要素が無い）。選択中のタブを再クリックすると右ペイン先頭へスクロールする（`scrollIntoView({ behavior: "smooth", block: "start" })` で、PC の独立スクロールでもスマホの window スクロールでも祖先を辿って揃う）。
* 次のスクロール位置等は `RightPaneContext`（`<Routes>` の外、インメモリ）にポストID・画面ごとに記憶し、ブラウザバックで戻ったときに復元する。
  * 「前後のポスト」のスクロール位置（離れる直前に保存。記憶が無ければターゲットの位置へ）。
  * 返信先の遡りチェーンと中央ペインの `window.scrollY`。チェーンを再取得して高さが確定してから1度だけ復元する。リンククリックで離れるときは、Router が DOM を差し替えて `scrollY` が変わる前に、`AppShell` の `onBeforeNavigate` で同期的に確定する。
  * 【クイック通知】（`.rightScroll` の `scrollTop`）と通知画面（`/notifications`、`window.scrollY`）。`NotificationsPanel` は `scrollY`/`onScrollYChange`/`getScrollContainer`（省略時 `window`）と `cache`/`onCacheChange` の props を持ち、呼び出し元がコンテナと記憶先を渡す。
* **`NotificationsPanel` の復元で守ること**（どれも、DOM の実高さが一瞬縮んでブラウザがスクロール位置をクランプし、それを継続保存リスナーが正しい記憶の上に書いてしまうのを防ぐため）:
  * スクロール位置だけでなく一覧本体（追加読み込み分を含む）も記憶し、戻ったら再取得せずそのまま出す。先頭ページ（20件）だけを取り直すと、深く読み込んでいた位置に届く高さが無い。離脱中の新着は `sinceId` で補って先頭に足し、既読にする。
  * キャッシュは `useEffect` で `setItems` せず、`useCursorPagination` の初期値として渡し、初回レンダーから表示する（最初の1回が空一覧になるとその瞬間にクランプされる）。同じ理由で、新着の差分取得・既読処理の完了を `loadingInitial` に待たせない（fire-and-forget）。
  * 遷移を起こすクリック（`<li>` の navigate、通知者名などの `<a href>`）の瞬間に現在値を確定して凍結し（`freezeScroll`、`navigatingAwayRef`）、以後の保存を止める。アンマウント中に DOM が取り除かれて高さが縮み、一覧が長いほどその間の `scroll` イベントを拾ってしまうため。通知アイテムの遷移は `<a href>` ではなく `<li onClick>` なので、`AppShell` の `closest("a[href]")` では拾えず、パネル内で個別に対処している。

### 2.4a 中央ペイン（ホーム画面）のフィードタブ・スクロール位置の維持ルール
* フィードタブ（ホーム/ローカル/ソーシャル/グローバル/リスト/ハッシュタグ）の選択・取得済みの一覧・スクロール位置は `HomeFeedContext`（`<Routes>` の外）に保ち、他画面から戻ったりタブを行き来したりしても再取得せず復元する（タブごとにキャッシュ）。選択は localStorage にも保存し、リロード後に復元する（無い・壊れていればホーム）。
* 選択中のタブを再クリックすると `window.scrollTo({ top: 0, behavior: "smooth" })` で先頭へ（`handleFeedTabClick`）。
* タブ切替の直後は、新しいタブの一覧が復元・取得されるまで前のタブの一覧が画面に残る。一覧がどのタブのものか（`notesFeedKey`）を持ち、表示中タブと一致しない間はキャッシュへの書き込み・次ページ取得・先頭補完のマージをしない。切替前に始めた次ページ取得・先頭補完は完了しても捨てる（次ページは `useCursorPagination` の `resetKey` の世代で判定）。そうしないと、素早く切り替えたときに別タブの投稿が一覧やキャッシュに混ざる。
* このセッションで一度も表示していないタブに切り替えたら、前のタブのスクロール位置を持ち越さず即座に先頭へ戻す（読み込み前後で高さが変わり、スマホ幅ではタブシートまで巻き込んでスクロールしてしまうため）。
* 狭幅（`useIsNarrowViewport`）では右ペイン（通知/トレンド・検索）自体を描かない。ホームの中央ペインは無限スクロールで終わりが無く右ペインに辿り着けないのに、`NotificationsPanel` はマウント時に通知を既読にしてしまうため（中央へ差し込む代替もしない。「実際に見た」を保証できない）。

### 2.4b 投稿フォームの操作ボタン（#152）
* 本文の直下の1行に、ポスト言語・Fediverse 配送・Bluesky 配送（同梱のロゴ SVG の正方形ボタン）・メディア添付（線画の自作 SVG。「図画」に合う絵文字が無いため）・アンケート・CW・絵文字挿入・ユーザーID挿入・残り文字数（右寄せ）を並べる。公開範囲はここでは選ばない。
* **ポスト言語**: 選択中の言語を2文字コード（`JA` 等）で出す正方形ボタン。クリックで「`JA 日本語`」形式の7言語のリストを開く。初期値は現在の表示言語で、配送先トグルのような「最後に送った値」は記憶しない。Bsky の `langs` にだけ反映する（`docs/protocols.md` 3節）。
* **投稿ボタン**: フォーム最下段に 🌐 投稿（パブリック）・🌙 ひかえめ・🔒️ プライベートの3つを並べ、押したボタンの公開範囲で投稿する（両立しない組み合わせを選ばせてからエラーで弾く体験を避けるため）。
  * Bluesky 配送がオンの間は 🔒️ をグレーアウトする（Bsky は followers_only を配信できない）。ホバー/クリックで Bluesky ロゴ付きの吹き出し「Blueskyをオフにするとプライベート投稿ができます」を出す。disabled の button はポインタイベントを拾わないので、判定は親の wrapper で行い、button は `pointer-events: none`。
  * 引用対象が「ひかえめ」なら 🌐 をグレーアウトする。
  * 返信では、配送ボタンは返信先が実体を持つプロトコルだけ出す（`replyFediAllowed`/`replyBskyAllowed`）。公開範囲は返信先より広いものを出さない（ひかえめなら 🌙🔒️、プライベートなら 🔒️ だけでその旨も表示）。Bluesky 配送がオンなら 🔒️ はグレーアウトではなく非表示にする（返信では選択肢が動的に絞られるので、押せないボタンは無い方が分かりやすい）。
* **既定の投稿ボタン**（Ctrl+Enter 等の送信先）を5pxの赤枠（`box-shadow`。既定のフォーカスアウトラインは `:focus-visible` で無効化）で示す。Tab で投稿ボタンにフォーカスがある間はそのボタン、外れると、通常投稿・引用は最後に送信したボタン（`localStorage` の `seiran:composer-defaults`、配送先トグルも一緒に記憶）、返信は返信先から決まる既定値（`replyVisibilityConstraint`）。既定のボタンがグレーアウト中でも赤枠は消さず、その状態でショートカットを押すと送信せずにパブリックのボタンへフォーカスを移す（意図しない公開範囲で黙って送らないため）。
* **矢印キー**: 投稿ボタン列の中は左右キーで移動し（グレーアウトは飛ばし、端で反対側へ回る）、上キーで Bluesky 配送ボタンへ。操作ボタン列（表示中のもの、最大7個）も左右キーで移動し、上キーで本文（`ComposerEditor` が `forwardRef` で公開する要素）へ、下キーで既定の投稿ボタン（グレーアウトならパブリック、それも駄目なら何もしない）へ。
* 投稿フォームの行コンテナ（`.form`/`.controlRow`/`.bottomRow`/`.footer`/`.postBtnGroup`）は NoteCard と同じく `min-width: 0` を徹底し、狭幅で折り返しても子要素がページの横幅を押し広げないようにする（`body` の `overflow-x: hidden` との二重の対策）。
* **本文欄の高さ上限は `PostComposer` が画面の残りから動的に計算する**（固定の vh だと、低い画面では投稿ボタンが画面外に押し出され、高い画面では余白が余る）。`<form>` の高さから本文欄の高さを引いた「本文欄以外の高さ」を実測し、（モーダル内ならスクロール可能な祖先の下端、無ければビューポートの下端）からフォーム上端・本文欄以外の高さ・下余白16pxを引いた値を `max-height` に設定する。`ResizeObserver` で `<form>` の高さ変化を、`resize`/`scroll` でも再計算する。上限に達したら本文欄が `overflow-y: auto` になり、投稿ボタンは常に画面内に残る。新規投稿ダイアログも `.dialog` に `max-height: calc(90vh - 16px)` と flex、`.body` に `overflow-y: auto` を持つ（本文以外が長い場合の保険）。
* **複数添付（#227）**: `<input type="file" multiple>` で最大10件。プレビューは最下段の横並びグリッドで、個別に削除できる。
* **Bsky embed 選択のラジオボタン（#227）**: Bluesky 配送オンの間、添付（非アニメ静止画グループ・アニメGIF・動画/音声それぞれ）と本文中の URL（最大5件）を合わせた候補について、次のときラジオボタンを出す（`.attachGrid` とは別の行、`.bottomRow` は縦積み）。
  * 候補が2件以上ある。
  * 本文に URL が1件でもある、または URL を既に選んでいる。添付も URL も無い状態からリンクカードを付ける唯一の手段が「本文に URL を書く → 選ぶ → 本文から消す」なので、URL だけの1件でも出す（Bluesky の「URL を貼るとプレビューが出て、文字列を消してもカードは残る」に相当）。
  * URL 以外の候補1件だけなら出さない（曖昧さが無い）。
  * アニメGIF・動画/音声の候補には小さな正方形サムネイル（`DriveFile.thumbnailUrl`）を添える。
  * 送信を止めるのは「候補2件以上で未選択」のときだけ（URL 1件だけなら未選択でもバックエンドの優先順位で採用される）。
  * 選んだ URL を本文から消しても選択は残り（孤児）、他を選び直すと消える。Bluesky 配送をオフにするとリストも選択も消える。
* **URL カードのチェックボックス**: ラジオが出ない状態（Bluesky 配送オフか CW 中）でも本文に URL があれば、チェックボックス（複数選択。seiran は1投稿に複数のカードを持てる）を出す。候補と孤児の扱いはラジオと同じ。ラジオが出る状態に切り替わった瞬間、チェック済みで表示順が最も上の URL をラジオの選択に引き継ぐ（明示の選択があれば上書きしない）。送信は止めない。
* **アンケート（#228）**: 📊 トグルで、選択肢（初期2件、+ で最大10件、× で最小2件）・複数選択・期限（無期限/日時指定/5分〜7日のプリセット）を出す（`.bottomRow` 内の独立した行）。添付との併用は可。非空の選択肢が2件揃うまで送信できない。アンケートは Bsky embed 候補の先頭（最優先）。閉じると設定はすべて消える。
* **CW（#229）**: ⚠️ トグルで、ガイド文の1行入力（100書記素、残り文字数表示）を出す（アンケートの上の行）。添付・アンケートとの併用は可。空か100書記素超の間は送信できない。CW 中は Bsky embed のラジオ自体を出さない（隠れた中身は常にリンクカードから詳細ページで見る設計なので、選ぶ余地が無い）。閉じるとガイド文は消える。

### 2.4c 中央ペイン上部の常設投稿フォームの折りたたみ
* タイムライン画面の上部に常設の投稿フォームはトグルで開閉でき、状態は `localStorage`（`seiran_composer_collapsed`）に保存する。
* 新規投稿ダイアログを投稿せずに閉じたら、書きかけ（本文・添付・配送先・公開範囲）を表示中の常設フォームにすぐ反映する。

### 2.4d フィードタブのスクロール追従
* フィードタブは下にスクロールしても画面上端（`top: 0`）に張り付く（各画面はタイトル見出しを持たないので、タブ自身が上端の sticky 要素になる）。

### 2.4e タイムラインへのリアルタイム新規ポスト挿入時のスクロール位置維持
* WS で届いた新着（自分の投稿を含む）は一覧の先頭に入る。最上部（`window.scrollY === 0`）にいれば押し下げアニメーション（`.entering`、0.4秒で高さを展開）付き。
* 最上部でなければ、アニメーション無しで確定した高さで挿入し、増えた高さ（挿入前の `scrollHeight` との差）を `scrollY` に足して、見えているポストが動かないようにする。

### 2.4f 復帰時・WebSocket再接続時のタイムライン再同期
* 次の2つのタイミングで先頭ページ（`PAGE_SIZE` 件）を取り直してマージする（`mergeHeadIntoTimeline`）。
  * 他画面から戻ったとき（キャッシュ復元の直後）。離脱中は購読が切れているので新着・リアクション・削除が反映されていない。
  * WebSocket の再接続時（`subscribeChannel` の `onResync`）。
* 取り直した先頭ページと現在の一覧をノートIDで突き合わせ、重なった位置より新しい分だけを先頭に足す（アニメーション無し、2.4e と同じ位置補正）。
* まったく重ならなければ（`PAGE_SIZE` 件を超える取りこぼし）、取れた分を足した上で境目に取りこぼしの可能性を示す区切り線（二重の波線、SVG マスク）を入れる。位置（直後のノートID）は `gapBeforeIds` としてキャッシュに保存する。区切り線の上マージンは NoteCard 間の余白（`.card` の `margin-top: 12px` ＋区切り線の `margin-bottom: 2px` = 14px）に揃える。

### 2.4g タイムライン画面のスワイプ操作（モバイル）
* 左スワイプで次のタブ、右スワイプで前のタブ（表示順、端では止まる）。
* 縦スクロールとの誤検知を避けるため、横移動が縦の1.5倍以上かつ50px以上のときだけスワイプとみなす（`useSwipe`、`touch-action: pan-y`）。
* 切り替え後、アクティブなタブがタブバー内で見えるよう `scrollIntoView` する。

### 2.5 【メッセージ（DM）画面】表示時
* **右ペイン:** メッセージセッション（スレッド起点が同じ direct 投稿の集合）の一覧。相手のアイコン・名前・最終メッセージのプレビュー・未読ドット。「新規メッセージ」で宛先未選択の作成画面へ。自分以外の参加者全員がミュート/ブロック対象のセッションは一覧にもバッジにも出ない。
  * プレビュー（`.sessionPreview`）は1行省略（`nowrap` + ellipsis）。長い連続文字列で画面が広がらないよう `.sessionPreview` と祖先の `.right` にも `min-width: 0` を付ける（flex の自動最小サイズにはコンテンツの幅が伝わるので、`overflow: visible` の `.right` にも明示が要る）。
  * 最終メッセージが CW 付きなら本文の代わりに「⚠️ CWラベル」だけを出す。
* **中央ペイン:** 選択中のセッションのメッセージを時刻順（ツリーにしない、一番下が最新）に出し、その下に送信フォーム（宛先 chip ＋テキスト）を固定する。
  * 既存セッションでは宛先 chip が相手で埋まる。
  * 宛先に Bsky アクターがいれば文字数上限が Bsky DM の1000書記素になり、添付ボタンが消える。
  * Bsky アクターと他プロトコルのアクターを混ぜようとすると警告の吹き出しが出て、競合する chip が赤字になる（Bsky DM は1対1のみ）。
  * 参加者3人以上のスレッドでは、各メッセージの先頭に「宛先:」とそのメッセージの宛先のアバター（`NoteResponse.recipients`、16px。ホバーで `@username[@domain]` と名前）を出す。宛先はメッセージごとに違いうるので、スレッド全体の参加者ではなく個々の宛先を見せる。1対1では出さない。
  * 本文は `MessageContent`（CW・添付・リンクカード・引用・アンケート結果）で描く。作成フォームは CW・アンケート・引用を作れないが、受信した DM には含まれうる。アンケートは結果表示だけ。
  * 本文（`.messageText`）は `overflow-wrap: anywhere`、`.messageRow`/`.messageBubble` は `min-width: 0`（長い URL で横に広がらないように）。
  * **リアクション（LINE 風）:** 吹き出しの外側下部に `MessageReactions` で出す。数は出さず、同じ絵文字は個数分並べる。
  * **右クリックメニュー:** 「リアクション」と「削除」。fedi/local のみのスレッドは1メッセージ1リアクション、自分のメッセージだけ完全削除できる。Bsky を含むスレッドは Bsky のチャット API の制約（Unicode 絵文字のみでピッカーのカスタムタブを隠す、1メッセージ最大5個、同じ絵文字は1個）に従い、「削除」は「隠す」（自分の画面からだけ消す。確認文言も変わる）になり、自分と相手どちらのメッセージにも出す。
* **左ペインのバッジ:** 未読のあるセッション数。

### 2.6 【通知画面】（`/notifications`）表示時
* **中央ペイン:** タイムライン右ペインの【クイック通知】と同じ `NotificationsPanel`。リポスト（🔁）・引用（❝）も同じ一覧に出し、通知文から新しいリポスト/引用投稿へ遷移できる。window スクロールなので、`window.scrollY` と一覧本体を `RightPaneContext` に記憶して戻ったら再取得せず復元する（2.4節）。
* **右ペイン:** 【トレンド＆検索】固定。
* 通知アイテムとプロフィールのリアクションイベント（`ReactionEventCard`）は、ホバーで対象ポストのダイジェストを `NoteHoverPreview` で横に出す（下に出すとマウスが乗って消えず、下のアイテムを押せなくなる）。横に出すときは吹き出しの三角を付ける（真下に出すものには付けない）。
  * `NotificationsPanel` は右ペイン（アイテムが右寄りで左に余白が大きい）と中央ペイン（左寄りで左の余白がナビ分しかない）の両方で使うので、アイテムの `getBoundingClientRect()` から左右どちらに320px＋余白の空きがあるかを判定し、空いている側（左優先）に `position: fixed` で出す。どちらも空いていない（スマホ等）ときだけ真下（吹き出し無し）に出す。

### 2.7 【設定画面】（`/settings` 以下）表示時（#55）
右ペインは使わず中央ペインのみ。
* **`/settings`**: アカウント・プロフィール・ミュート/ブロック・プライバシー・リスト・表示・アプリトークンへの導線。「承認待ちフォロー」は `is_locked` が有効な間だけ出し、件数を赤バッジで出す（左ペインの「設定」にも同じバッジ、`StreamingContext` の `followRequestCount`）。
* **`/settings/account`**: メールアドレス・DID の表示、メールアドレス変更（新アドレスに確認メールを送り、`/verify-email-change?token=...` で確定）、パスワード変更（現在のパスワード必須）、TOTP とパスキーの設定、退会。
  * TOTP は QR かシークレットを認証アプリに登録し、初回の6桁コードで有効化した後、二度と出ない10件のリカバリーコードを見せる。通常の無効化は現在のパスワードが要る。両方失ったらログインの2段階目から登録メールへ解除リンクを送り、`/totp-disable?token=...` で解除する。
  * パスキーは名前を付けて複数登録・個別削除できる。ログイン画面の「パスキーを使う」だけで、ID 入力なしにログインできる。
* **`/settings/profile`**（`ProfileEditPage`）: 表示名・Bio・プロフィール項目・アイコン・背景画像・「別のアカウント」の編集。
  * 背景画像はアイコンと同じ操作（変更 → 選択 → アップロード後にプレビュー、保存で `banner_media_id` を送る）で、16:5 の枠に `object-fit: cover`。未設定なら枠を出さない。
  * 「別のアカウント」はリストのメンバー追加と同じ UI（サジェスト付き入力・アバター/ハンドル/種別バッジ付きの一覧・削除）で、説明は「相手アカウントからもこちらを登録していれば✅️がつきます。」だけ（Misskey 側の手順は `docs/protocols.md`）。
  * プロフィール画面では bio の直下に登録済みアカウントをバッジで並べ、✅（相互検証済み）はホバーで説明を出す。リモート Fedi アクターのプロフィールも同じ見た目（編集はローカル本人だけ）。
* **`/settings/mutes-blocks`**: 【ミュート中】【ブロック中】【リポストミュート中】のタブで一覧と解除ボタン。少数想定なので最大200件を一括取得する。
* **`/settings/privacy`**: 「投稿を Bsky のおすすめ（Discover 等）に表示しない」（Bsky 限定）と「新規フォローを承認制にする」（`is_locked`。投稿の公開範囲には影響せず、Bsky 側からの直接フォローは防げないことを説明文に書く。オフにすると残っていた承認待ちは自動承認される）。どちらもトグルで即保存する。
* **`/settings/follow-requests`**: 承認待ち（`is_locked` の間だけ）を1件ずつ【承認】【拒否】（最大200件一括）。処理した行はすぐ消え、バッジを取り直す。
* **`/settings/lists`**（`ListsSettingsPage`）: メンバー検索は先頭 `@` を含む生の入力で、表示名・Fedi ID・Bsky ハンドル・ローカル短縮ID・ローカルの Fedi/Bsky ID を横断して大文字小文字を無視した部分一致。
* **`/settings/app-tokens`**（#60）: 発行済みアプリトークン（MiAuth と画面から直接発行した分。自社ログインは対象外）の一覧と個別無効化。上部の「用途（任意）」と発行ボタンでその場で発行できる。トークン本体は発行直後の応答にしか無い（DB には `jti` だけ）ので、警告文とコピーできるコードブロックで一度だけ見せる。
* **`/settings/appearance`**: 
  * テーマ（環境に従う/常にライト/常にダーク）は `localStorage`（`seiran_theme`）だけに保存する。`ThemeProvider` が `<html data-theme>` を切り替え、CSS 変数で全画面に反映する。「環境に従う」は `prefers-color-scheme` の変化をリアルタイムに反映する。ちらつきを防ぐため React のマウント前に `index.html` のインラインスクリプトで `data-theme` を決める。
  * 言語（自動/日本語/English/繁體中文/简体中文/한국어/Español/Deutsch/Français）は選んだ時点で `users.language_preference` に保存し、`i18n.changeLanguage()` で反映する（`docs/architecture.md` 8節の i18n）。

### 2.8 【管理画面】（`/admin`）表示時
管理者・モデレーター専用（`isAdminRole`）。右ペインはプレースホルダで、中央ペインが本体。
* **タブ:** `Tabs` で【ユーザー管理】【サイトの設定】【ストレージ】【カスタム絵文字】【通報】【凍結済みユーザー】【リレー】【認証ブロック】（ロールごとに見えるトピックが違う、`docs/database.md` の `users.role`）。タブシートは `sticky`/`top` を渡したときだけ上端に張り付く（オプトイン）。モバイルでは左右スワイプで切り替える（判定は2.4gと同じ）。
* **サイトの設定**: ログイン/TOTP の種類数・時間窓、IP 自動ブロックの条件と期間、同一IPの登録数・時間窓、Turnstile の site key/secret（secret は再表示しない）、ロール別レート制限（user/moderator の閾値と時間窓）。Turnstile を設定するとログイン・登録フォームにウィジェットを出し、検証が済むまで送信できない。
* **認証ブロック**: ブロック中のIP・期限・理由の一覧と個別解除。
* **ユーザー管理**: ロール・凍結状態・TOTP の有無・パスキー数。TOTP が有効なユーザーには強制解除ボタン（確認後、シークレット・リカバリーコード・未使用の解除要求を消す）。パスキーは表示だけ。
* **ストレージ**（`StorageProvidersPanel`）: S3 互換ストレージの一覧（有効/無効・削除）と行ごとのインライン編集（名前・エンドポイント・バケット・リージョン・アクセスキー・公開URL・容量上限 MB、空欄は無制限）。シークレットキーは空欄のまま保存すると既存値を保つ。
* **凍結済みユーザー**: ローカル・リモート混在の凍結済みアクターの無限スクロール一覧と凍結解除（ローカルはメールアドレスも出す）。通報・ユーザー管理の凍結ボタンと同じ `actors.suspended_at` を更新する。
* **リレー**（#140）: HTTPS のリレー inbox を複数追加でき、承認待ち・参加中・拒否と最後のエラーを出す。削除すると Undo(Follow) を送って離脱する。
* **カスタム絵文字**（`EmojisPanel`）: 「ローカル」（一覧・追加・Misskey ZIP インポート・shortcode/タグの部分一致検索）と「リモート」（`remote_emojis` の一覧、300ms デバウンスの検索、各行の「インポート」で `EmojiImportDialog`（カテゴリ・タグ・ライセンス。ライセンスはリモートの値を初期表示））。
* **NoteCard の右クリックからの絵文字インポート**: 絵文字管理権限（admin/moderator/emoji-editor）で、本文・リアクションのリモート絵文字（このインスタンスに無い shortcode）の画像を右クリックすると `EmojiContextMenu` が出て、「絵文字をインポート」で同じダイアログを開ける。権限が無い・ローカル絵文字ならブラウザ標準の右クリックのまま。

### 2.9 凍結中のローカルユーザー向け専用画面（`SuspendedAccountPage`）
`GET /api/auth/me` の `is_suspended` が真の間、`AppRoutes` はどの URL でも他のルートを飛ばしてこの画面だけを出す（ユーザー名、「あなたは凍結されています」、ログアウトボタン）。ログアウトはクライアント側だけ（トークン破棄）。他の API はすべて `ACCOUNT_SUSPENDED` になるので、この画面からは何もできない。

## 3. ブリッジユーザーのインターセプション（案内）導線

ブリッジユーザー（Bridgy Fed 等が別プロトコルへ投影したアクター）を閲覧・操作したとき、フロントが介入して実ユーザーへ誘導する。

### 3.1 実ユーザーへのワープ機能
* `bridge_real_actor_id` があるアクターのプロフィールでは、最上部（「リモートで表示」と同じ `RemoteBanner`）に「ブリッジユーザーです【実ユーザーを表示】」をプロトコルアイコン付きで並べる（ハンドル文字列は埋め込まない）。

### 3.2 フォロー時のインターセプト
* ブリッジユーザーの「フォロー」を押したら、すぐには送らず次の確認モーダルを挟む。

> **「このアカウントは、Bluesky（またはFedi）のユーザーがブリッジ経由で投影されているブリッジユーザーです。 seiranの機能をフルに活用するため、実ユーザー（オリジナルアカウント）を直接フォローすることをおすすめします。実ユーザーをフォローしに行きますか？」**
> * [ボタンA]: 実ユーザーのプロフィールへ移動してフォロー
> * [ボタンB]: そのままブリッジユーザーをフォロー（互換維持用）

### 3.3 リモートポスト・ユーザーの明示（「リモートで表示」バナー）
* ローカルでないポスト詳細・プロフィールでは、最上部に `RemoteBanner`（「リモートのポストです」/「リモートのユーザーです」＋別タブで開く「リモートで表示」リンク）を出す。
* リンク先は AP を優先し、無ければ bsky.app（`https://bsky.app/profile/{did}[/post/{rkey}]`）。ポストは `NoteResponse.remoteUrl`、プロフィールは `ap_uri`/`at_did` から作る。AP の URL が `/activity` で終わっていれば取り除く（Misskey・Mastodon 等は Activity の `id` を `{閲覧用URL}/activity` で発行するため）。
* リポストの詳細では、リポストラッパー自身（リポストした人）でリモートかどうかとリンク先を決める（元投稿がリモートかどうかは関係ない）。ブリッジユーザーの導線とは独立で、両方出ることもある。

## 4. グローバル通知（トースト）

## 4.1 サーバー詳細ダイアログ・更新要求ダイアログ

LeftNav の左下（ユーザーチップの下）に「Powered by Seiran」ボタンを置き、`ServerInfoDialog`（タイトル「Seiran」、GitHub へのリンク、フロントとサーバーのバージョン、アイコンは GitHub 組織のアバター）を開く。サーバーのバージョンは API のレスポンスを受けるたびに更新されるので、開いたまま再デプロイされても次の API 呼び出しで追随する（`docs/architecture.md` 2.1節）。左ペインがアイコンのみに畳まれたら隠す。ログイン画面のフォーム下部にも同じボタンを置く。

互換性チェックに引っかかったら `ReloadRequiredDialog` が「画面の更新が必要です。リロードしてください。」を出す。閉じるとその場では再表示しない。

## 6. 投稿カードの補足

### 6.1 アンケート
* 未回答・締切前は回答 UI を出し、結果表示と切り替えられる。単一選択は選択肢のクリックで即回答、複数選択はチェックして回答ボタン。回答後・締切後は結果表示に固定する。
* 回答済みかどうかと自分の選択はサーバーの値（`votedByMe`）から復元し、リロードしても再回答 UI に戻さない。結果では自分の選択肢にチェックを付ける。
* リポストされたアンケートもカード内に同じ状態で出す。同じ画面に同じアンケートが複数あれば投稿ID単位の共有状態（`pollVoteStore`）を購読し、どれかで回答したら全部が結果表示になる。
* **残り時間**: `endTime` があり未回答・締切前なら、「結果を見る」の右に残り時間（`PollCountdown`）を出す。1分未満は秒、1時間未満は分、1日未満は「＊時間＊分」、それ以上は「＊日＊時間＊分」（切り捨て）で1秒ごとに減る。`stores/secondTicker`（購読者がいる間だけ `setInterval` を1本動かす共有タイマー）を `PollCountdown` だけが購読するので、`NoteCard` 全体は再描画しない。期限を過ぎたら消える。
* 締切済み（`poll.closed` か `endTime` 経過）は結果表示だけにし、回答 UI・「結果を見る」・残り時間の代わりに「投票終了」を出す（未回答のまま締切を迎えて回答ボタンが見当たらず混乱しないように）。
* CW の案内文は地の文、次の行に開閉ボタン、開いた本文はボタンの次の行。閲覧注意画像をライトボックスで開いたときの解除ボタンは、ライトボックス画像の右上。

### 6.2 引用ポストカード
* 引用ポストは自身の本文の直下に、引用元を枠付きカードで1段だけ出す（返信マーカー・ユーザー名・本文（CW は案内と開閉ボタン）・時刻・添付・アンケート・リアクション）。引用元がさらに引用を持つなら「引用あり」とだけ出し、入れ子にしない。引用元が見えなければ API が `quote` を埋め込まないので、引用元へのリンクだけを出す。
* アクション列とメニューの「引用」で、引用元の投稿者・本文を確認できるコンポーザを開き、通常投稿と同じ本文・添付・公開範囲・配送先で引用を作る。

### 6.3 未取り込み参照の表示（`PendingReferenceIndicator`）
参照先が `pending`（未取り込み）/`gone`（消失確定）のとき、`Note.replyStatus`/`quoteStatus`/`renoteStatus`（対応する `*Id` が無いときだけ意味を持つ）に応じて出す。`pending` は「未取り込み」と取り込むボタン、`gone` は案内だけ。
* リプライ: カード最上部の関係行に、`ReplyIndicator` の代わりに出す。
* 引用: 引用カードの位置に出す（見えないため `quote` が無いだけで `quoteId` はある場合とは別の状態）。
* リポストラッパー: rail はそのまま出し、元投稿カードの位置に出す（誰かが何かをリポストしたことは分かるように）。

取り込むボタンは `POST /api/notes/:id/resolve-reference`（`{"kind": "reply"|"quote"|"repost"}`）を呼び、`resolved` ならリプライはその場で `ReplyIndicator` に、引用・リポストは取得して埋め込みカードに切り替える（ページの再読み込みは不要）。`pending`/`gone` ならその状態に更新する。ポスト詳細を開いた時点でもサーバーが自動で解決を試みるので、押す前に解決していることも多い（`docs/protocols.md` 1節）。

### 6.4 凍結ユーザーの投稿を参照する場合の表示
引用カード・リポストの元投稿・ポスト詳細の返信先の小カードは、参照先が `Note.authorSuspended` なら本文・添付・URLカード・アンケート・リアクションを「凍結されたユーザーのポストです」に差し替える（`PostContent` の `isMainSubject` が偽のとき）。カードはクリックでき、詳細へ行けば実データが読める。詳細画面の主役（`isMainSubject`）は凍結ユーザーの投稿でも差し替えない。タイムライン・検索・ハッシュタグには凍結ユーザーの投稿自体が出ない（`docs/database.md`「`actors.suspended_at`」）。

## 7. ログイン画面

`/login`・`/register`・`/register/migrate` は1つの画面（`pages/auth/AuthCarouselPage`）で、URL はアクティブなフォームの違いにだけ反映する（`/register/migrate/status` は転入の進行状況の独立ページ）。

### レイアウト
- 幅880px以上は横並び: 左〜中央がサイトタイトル表示エリア（440〜900pxで伸縮）、右が幅440px固定のフォーム。
- 880px未満は縦積み: タイトルエリアが上、フォーム（最大440px、中央寄せ）が下。
- タイトルエリアは上下2分割し、上半分の下端にサイトタイトル、下半分の上端に右寄せでサイト説明文を置く。
- 背景は既定でサイトカラーを白に混ぜた色（`color-mix(in srgb, var(--accent-strong) 12%, white)`）。管理画面で「ログイン画面背景」（`login_bg_url`/`login_bg_type`）に画像か動画を設定したらそれを全面に敷く（動画は `autoplay loop muted playsinline`）。アップロードは `POST /api/drive/files/create` の `media_type=login_background`（この種別だけ動画・音声も許可、投稿に紐づかないので Bsky 動画パイプラインへは出さない）。

### サイトタイトル・説明文
- サイトタイトルは「サイト名」（`site_name`）を HTML のまま描く（管理者専用の入力なのでサニタイズしない）。nodeinfo の `nodeName`・PWA のマニフェスト名・OGP の `og:site_name`・`<title>` には HTML タグを除いたプレーンテキスト版を使う（`notes/validation.rs::strip_html_tags`、`seiran-federation-inbox` の nodeinfo は同等の軽量実装を持つ）。`POST /api/meta` は `name`（タグ除去済み）と `siteTitleHtml`（生の HTML）の両方を返す。
- タイトルの文字サイズは `hooks/useFitTextSize.ts`（ResizeObserver ＋二分探索）で、改行せず幅に収まる最大値を都度計算する（上限は横並び144px、縦積み72px）。
- 説明文は「サイト説明テキスト」（`site_description`）を HTML のまま右寄せで出す（`white-space: pre-wrap` でプレーンテキストの改行も効く）。

### フォームエリア（縦カルーセル）
ログイン・サインアップ・Bluesky から転入の3パネルを縦に並べる。非アクティブなパネルは見出しボタン（クリックで対応するルートへ）だけの高さに縮み、アクティブなパネルはフォーム全体を展開する（`max-height` のアコーディオン）。3パネルは常にマウントしたまま CSS で開閉するので、メール確認送信済みや2FA入力中といった途中状態はパネルを切り替えても残る。共通のフッターに「powered by Seiran」ボタンを1つ置く。

## 8. Unicode絵文字の表示（twemoji）

Unicode 絵文字（本文・表示名・リアクション・ピッカー・装飾アイコン等）は OS/ブラウザのグリフに任せず、jdecked/twemoji（`@twemoji/parser` + `@twemoji/svg`）の SVG をセルフホストして統一する。アセットは postinstall で `scripts/copy-twemoji-assets.mjs` が `frontend/public/twemoji/` にコピーする（git 管理外）。

- `lib/twemoji.tsx`: `@twemoji/parser` を `buildUrl: (codepoints) => "/twemoji/${codepoints}.svg"` でラップする。
- `components/common/TwemojiImg`: `<img>` を描く部品。読み込みに失敗したら OS のグリフにフォールバックする。parser（17系）と svg（15.0.0で更新停止）のカバレッジがずれていて、新しい結合絵文字等で 404 になることがあるため。
- `TwemojiEmoji`: 絵文字1つを変換する（絵文字でなければそのまま）。ナビアイコン・バッジ・通知アイコン等。
- `TwemojiText`: 絵文字混じりのラベルの絵文字部分だけを変換する（`ActionsMenu` の項目等）。
- `components/note/EmojiText`: カスタム絵文字を画像にした残りのテキストにも同じ変換をかける（本文・表示名）。

絵文字は `<img alt="...">` になって `textContent` に含まれないので、テストでは `textContent` ではなく `getByRole` のアクセシブル名で判定する。
